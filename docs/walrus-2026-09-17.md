## Learnings

- **The MCP server name (FastMCP constructor) is what Gemini displays as the @mention.** Renaming the display requires editing the constructor name and re-syncing Gemini's app — or remove/re-add to force a refresh.
- **`await client.get(...).method()` chains the method on the coroutine** — assign the response first, then call the method. Caught by tests.
- **FastMCP's DNS-rebinding protection**: localhost hosts auto-allow `127.0.0.1:*`, `localhost:*`, `[::1]:*` — but forwarded Host headers (the Funnel's `ts.net`) need explicit `allowed_hosts`, and **portless HTTPS Hosts need the bare hostname** (the `:*` wildcard only matches ported Hosts).
- **The memory service (mcp-memory-service 4.1.1) speaks plain stateless JSON-RPC** (2024-11-05, no session id, no SSE) — the newer streamable-HTTP handshake fails with a TaskGroup JSONDecodeError. The caller now talks to it directly via httpx.
- **The service's tool names are raw**: `retrieve_memory`, `store_memory`, `delete_memory`, `recall_memory` — not the wrapped names visible in this session's toolset.
- **Provenance belongs in the service's native `client_hostname` field** (plus `metadata.client` redundantly). The service doesn't return it in search briefs — recorded gap.
- **Gemini's UI interprets a 401 as "could not be reached"** during its initial reachability probe — a retry succeeds (the 401 is the OAuth trigger working as designed). Gemini's per-call consent (Allow/Deny) is a *stronger* posture than a one-time OAuth grant.
- **Service-side dedup**: identical memory content returns no content_hash (the service deduplicates). Smoke scripts must use timestamped content.
- **Enforcers are for truth-flips, not prose cops**: the enforcer extension was rejected because it covered the benign class (stale prose, 100% caught by audit cadence) while the harmful class (runtime contract breaks) can't be string-matched. Value-vs-scope strikes are the Owner auditing the Steward's proposals.

## Decisions

- **Capability scoping: least-privilege writes** — consumers get read on all visible channels, write only on explicitly granted channels. Gemini = memory read/write; github read-only.
- **Snippet_length server-side** — gemini sees truncated content; the full text never crosses the trust boundary. The truncation is applied at the registry-scope level, not in the adapter.
- **Query-driven channels skip TTL cache** — memory retrieval runs against the prompt every call; caching would serve stale results for different queries.
- **OAuth-issued tokens mint into the runtime token map** — the resolver sees them exactly like config-registered tokens. One identity path, two token provenance classes (config-registered vs OAuth-minted).
- **Gate-strike: the scrub deferral is a module postponement, not a channels blockade** — Steward-authored gate language struck after Owner challenge ("WHO REQUESTED THAT???"); the module builds when built, the channel builds when valuable.

## Tradeoffs

- **`__main__` 0% coverage** — Acceptable class (stdio + HTTP entry, subprocess-only); the HTTP branch (`main_http`) is untested.
- **Secret-scrub deferred** — accepted risk: message-body channels serve unredacted content until the scrub builds; the first candidate (Telegram) is postponed anyway.
- **Direction churn unrecorded mid-thread** — struck framings lived only in chat; the debt issue carries the surviving consideration.
- **OAuth volatile state** — engine restart requires Gemini re-auth; acceptable for single-operator use.

## Alternatives

- **Sidecar OAuth endpoint** — rejected: duplicates the engine's scoping outside its consumer model ("via ichnos" means the engine IS the endpoint).
- **Playwright drives Gemini** — rejected: makes Gemini an automation target; the operator loses their interactive UI; Google anti-bot risk on the account.
- **MV3 Chrome extension** — viable upgrade path from the userscript; not needed (Gemini native MCP replaced the userscript entirely).
- **Memory channel as read-only** — Owner ruling: read/write, "similarly to how it's available here"; capability model extended to match.
- **Transport-layer 401 for unknown tokens** — rejected in favor of tool-level explicit errors: the ASGI middleware approach was deferred as a hardening step; tool-level errors are testable through the real path.
