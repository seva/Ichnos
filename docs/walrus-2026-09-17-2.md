## Learnings

- **xAI's rmcp client completes OAuth but does not attach the Authorization header to MCP requests.** Verified with diagnostic logging: `auth_header=(none)` with 11 known tokens. The connector's auth card shows "Connected" — the client *has* the token but the Rust transport layer doesn't inject it. Worked around server-side: unauthenticated requests default to the `web` consumer (Owner-sanctioned tradeoff — the Funnel URL is the access gate).
- **The memory service (mcp-memory-service 4.1.1) speaks plain stateless JSON-RPC** (2024-11-05, no session id, no SSE) — the newer streamable-HTTP handshake fails with a TaskGroup JSONDecodeError. The caller now uses direct httpx JSON-RPC POSTs (init → notification → tools/call).
- **The service's tool names are raw** (`retrieve_memory`, `store_memory`, `delete_memory`, `recall_memory`) — not the names visible in this session's toolset (which are the MetaThrone/grok-mcp wrapper names).
- **Provenance is stored but not surfaced**: the service persists `metadata` and `client_hostname` on store but `retrieve_memory` doesn't return them. `list_memories` DOES return metadata (42/50 entries carry it). The engine's provenance ledger compensates: it tracks hash → consumer for all engine-mediated writes, and enriches briefs at read time.
- **FastMCP's DNS-rebinding protection** auto-allows `127.0.0.1:*`, `localhost:*`, `[::1]:*` — but forwarded Host headers (Tailscale Funnel's `ts.net`) need explicit `allowed_hosts`, and **portless HTTPS Hosts need the bare hostname** (the `:*` wildcard only matches ported Hosts).
- **`build_http_app_from_config` returns the wrapped ASGI app, not FastMCP** — `main_http` serves it with `uvicorn.run()` directly, not `FastMCP.run()`. The separation: `build_http_server` → FastMCP object (for programmatic use/testing), `build_http_asgi` → wrapped Starlette app (for deployment).
- **Grok chat as a peer reviewer works through the grok-research proxy** — the review was grounded in the actual auth/capability surface (Grok probed `get_context` live before commenting). This is the Critic role exercised from the consumer's vantage point.
- **`async with` statements must be combined** (SIM117) when nesting — and Python's `async with (A as x, B as y)` syntax is the clean form.

The access gate is the Funnel URL's obscurity, not a credential check. Acceptable for single-operator use; a production deployment needs a real consent flow.
- **The gate-strike wording remains Owner-unclassified** — IMPLEMENTATION.md:52 still carries the "HARD PREREQUISITE" language (struck → reverted → restored); walrus-17 flagged it; G5 from audit #6 awaits Owner wording.

## Decisions

- **DCR default consumer = `web`** (Owner-sanctioned): DCR-registered clients carry no consumer hint; per-surface identity for web surfaces requires connector UIs to expose OAuth credential fields (xAI and Anthropic don't). Gemini's static client pins `gemini`.
- **Unauthenticated requests default to `web`** — declared tradeoff: the Funnel URL is the access gate. The `web` consumer must be present in the registry config; omitting it re-enables rejection.
- **Claude's wire name = `claude`** — MetaThrone is the persona, not the consumer. One wire name, no second.
- **OAuth token persistence** — issued tokens survive engine restarts. The volatile-state tradeoff from walrus-16 is retired.
- **Provenance ledger over service metadata** — the service stores provenance but doesn't return it on retrieve; the engine's ledger compensates for all engine-mediated writes and enriches at read time.

## Alignment

- Record-sync enforcer pins: scope position (L3/next-L4), opencode ruling, substrate options (headless-first), debt pointers (issue #3), structural-mark convention.
- Capability scoping: least-privilege write grants (default read-only); capability dimension orthogonal to channel filtering; snippet_length server-side.
- Identity resolution: token → consumer only (client_id is transport); client-supplied consumer names never trusted.
- Role separation: Grok's peer review (consumer-side Critic), Auditor verification, Operator rulings on scope decisions.

## Tradeoffs

- **Unauthenticated default to `web`** — the auth gate is the Funnel URL obscurity; anyone with the URL gets memory read/write as `web`. Accepted for single-operator use.
- **Auto-approve OAuth consent** — no user interaction on /authorize; redirect URIs pinned per client. Accepted for v1.
- **Gate-strike ambiguity** — the scrub language was struck, reverted, and the Owner hasn't classified the final wording. The ambiguity is operational (the module builds when built), not architectural.
- **OAuth state persisted but not encrypted** — `oauth_tokens.json` contains bearer tokens in plaintext. Same trust domain as cce.json (which holds the config). Production hardening: encrypt or move to the OS credential store.

## Alternatives

- **Sidecar OAuth endpoint** — rejected: duplicates scoping outside the engine ("via ichnos" means the engine IS the endpoint).
- **Transport-layer 401 for unknown tokens** — rejected in favor of tool-level explicit errors; the ASGI middleware approach was deferred as hardening.
- **Memory channel as read-only** — Owner ruled read/write ("similarly to how it's available here"); capability model extended.
- **MetaThrone as consumer name** — rejected: MetaThrone is the persona; `claude` is the wire name.
- **Reattribution of shared-window entries** — rejected: write-time `client_hostname` is the honest record; Grok confirmed reattribution is the wrong move ("do not attempt reattribution").
