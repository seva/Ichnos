## Learnings

- **The Socratic strikes were a lesson-delivery mechanism.** Nine challenges (substrate bias, n=1 platform induction, analogy-as-evidence, mirror-vs-source, direction-before-decomposition, consider-vs-execute, local-convenience-as-requirement) each cut a real reasoning defect. The residue is nine named error classes — worth more than any single decision they redirected.
- **Error messages carry their own pointers — read them whole.** The auth store path (`openclaw-agent.sqlite`) was inside the ProviderAuthError line; my log truncation hid it and I "fixed" the wrong store (`auth-profiles.json`). Cost: a full repair cycle to the wrong target.
- **Two auth stores exist and can silently diverge**: `auth-profiles.json` (json) vs `openclaw-agent.sqlite` `auth_profile_store.primary` (live). The gateway reads the sqlite and caches it in memory; sqlite writes require a gateway restart to be seen; json edits are inert.
- **`metathorneMessage.ps1` is gone** (deleted at some point post-March; memory stale). `openclaw agent --agent main --message` is the working self-service path — it executes a turn through the gateway and returns the reply directly, eliminating the operator-shuttle for tests entirely.
- **Single-substrate induction is a named error class**: "observed on Windows" became "Windows-only"; "installed here" nearly became "the source." Platform coverage claims come from the vendor's client matrix, verified per platform, never from the probe's substrate.
- **Read-only is the compliance shield, not just data hygiene**: the terminal bound's no-write rule is what makes walled-garden reads safe where protocol clones and client-driving are not. It does double duty and should be cited that way.
- **Backups must be verified before writes** — the opencode.json edit went in unbacked (parse error killed the backup in the same block); the auth-store fixes enforced verify-first and it paid off.
